## 判断依据

- 对照每题 Query、原审核素材、15个 Skill、来源会话和工具用途。旧255题审核清单中的3,484个工作区文件与当前内容一致，因此沿用原素材证据，并重点检查有争议的任务。
- 原有41道 Memory 题中，36题可参考此前62题实验的实际输入；其余5题是指定会话顺序读取题，不能写成已验证当前注入。
- `tdai_read_scene` 的理由只在已有实际输入记录支持时引用其中路径；这是该次准备的证据，不保证重新提炼后路径、内容仍相同。
- 搜索可以是找到正文或原话之前的合理入口，不要求一次调用完成任务；但不能仅凭“也是 Memory 工具”就接受任意工具。
- Skill 理由写明具体 Skill 与当前工作的关系。没有相关流程时，不因代码中出现某项技术名称就要求加载 Skill。

## 尚未验证的边界

1. 新30题均标记 `needs_confirmation / l3_unverified`。尚未运行其L1/L2/L3提炼和首次输入检查，不能断言答案必然不在System中。正式冻结前须确认提炼结果可查询、目标原话和出处是否已经完整注入，再裁定是否仍应调用。
2. 新题侧重历史材料核对与整理，不是30道完整Coding实现任务。若报告只讨论Coding任务，应将这一差异明确说明。
3. 工作区沿用对应项目模板并增加任务文档，不应称为30个独立真实项目。
4. 5道指定会话读取题仍受已知 Memory Bridge 覆盖 `session_id` 的实现限制影响。工具意图合理不代表当前后端能正确读取目标历史；本轮不修改核心实现，也不能把该限制归咎于模型选错工具。
5. `reason` 属于审核标签，不发送给执行模型。现有运行端隔离测试继续检查这一点。
