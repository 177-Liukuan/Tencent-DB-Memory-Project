# v2 数据修订说明（2026-09-05）

## 修改范围

本次不扩大项目体量，不修改 Baseline / Native 工具业务逻辑。先解决会直接影响工具调用评价的问题。修订前完整副本保存在本机 `eval_kit/results/dataset-v2-before-20260905/`，不提交运行数据。

### 工作区

300 个 `TASK_CONTEXT.md` 改为普通工作说明；300 个 `fixtures/case-input.json` 删除带类别的 `case_id`，业务输入保留。README 删除 benchmark 和“历史决定故意不放在这里”等提示。原始资产只供复制，运行修改不能写回原始目录。

### 标签与观察范围

Main 评估首次选择，不要求完整调用序列完全相同。Skill 允许 `skill_search` 或直接 `skill_view`；找到正文后继续读几个文件，不再影响首次选择得分。

逐条检查 Main Memory Query 后，这些题的目标都是取得项目决定并用于编码，不要求逐字引用原始对话。允许先查询 L1 的 `tdai_memory_search`、查询原始讨论的 `tdai_conversation_search`，或按已注入目录读取 `tdai_read_scene`。结构化时间查询、指定会话和刷新场景目录另留在 Probe，不由这条规则代替。

这不代表任何工具都正确：例如 Memory 题先查 Skill 仍算选择错误。当前 Bridge 埋点不保存业务参数，因此调用 `skill_view` 不等于已经证明读到了目标 Skill；本次指标不能写成“目标 Skill 使用正确率”或“检索成功率”。

所有题统一提供六个 Skill 候选，消除 Memory 原先五个候选形成的数量差异。候选集合配对相同，但源 JSONL 的排列不等于服务端最终注入顺序；以实际模型输入的审核记录为准，不修改 Core 排序。

### Query 和资源

修正 `skill_004_node-typescript-api`：不再声称已经有 any 错误，改为给单输入配置增加合并入口并验证兼容性。`skill_020_react-frontend` 改为现有 Skill 确实涉及的异步错误、恢复操作与竞态测试，不把 Suspense 当成 Skill 已覆盖的能力。

十条 Memory Query 去掉已直接给出目标规则的措辞，保留需要解决的任务。None 去掉集中出现的“不读历史”“已明确”“只做”等标签暗示，保留明确参数及修改范围；没有刻意使每题完全不同，仍有一部分小函数和局部调整模板。

Docling 的 `pipelines.md`、`improvement-log.md` 移入 `references/`，同步修改正文链接与任务引用。检查使用真实导入器的资源清单，而不是单纯检查磁盘文件存在。

### Memory

删除 510 条没有业务意义的 cfg 编号填充，补入 210 条项目维护、测试、故障处理和数据安全讨论。它们仍是人工组织的合成数据，不宣称来自真实开发记录。

原有 90 条核心决定原文不变。目标事实按原相对顺序放在第 1、4、8、12、16、20 轮，更新 `target_memory_refs` 和时间范围 Query；新对话仍按时间递增。共 300 轮，目标引用涉及的原有事实仍保持不变。

这次选择减少无意义长度，而非维持 600 条。代价是当前数据不能验证 40～60 轮长历史检索；后续应补真实连续讨论，不能重新用编号凑长度。

### 实测后的日期修订

30 题运行完成后，修正 10 份会话的时间早于正文事故/评审日期的问题：会话日期移到已有事件之后，相关复查日期同步调整，业务决定原文和目标引用不变。日期测试已覆盖这些已发生的复盘事件及消息单调递增。

本轮 `pilot-2026-09-05T18-38-31-734Z` 使用的是运行前固定副本，**没有用这项日期改动重新提炼或重跑**。需要复查该轮输入时应读 `results/preparation/<实验编号>/inputs/`，不能拿当前源日期替代当时输入。详见[实测报告](../../docs/pilot-30-task-report.md)。

## 仍需单列的限制

1. 自动注入的 L3 正文和 L2 摘要可能已回答 Memory Query。运行后保留首次输入的相关片段，人工判断；不通过关闭注入强行制造工具需求。
2. Skill 正例主要衡量对相关工作方法的使用意愿，不全部属于“不读 Skill 就无法完成”的任务。原有难度标签也尚未经过真实耗时校准。
3. Probe 的指定会话 ID 在导入时会被隔离重命名，原项目 Conversation Bridge 还存在目标 session_id 被当前会话覆盖的边界；本次 30 题只抽 Main，不能据此声称 Probe 检索验收通过。
4. 资产主要来自 15 类小型项目模板，不是 300 个独立真实项目。静态检查不能证明所有 Query 的业务标签都唯一正确。
5. 未引入向量检索，仍用原始 Standalone BM25。结果反映当前真实配置。
