# 线上发布与异常恢复

## 适用场景

- 执行应用版本发布、灰度扩容或配置变更。
- 发布期间错误率、延迟或资源使用出现异常。
- 需要停止发布、回滚版本或恢复上一份配置。
- 不适用于没有发布权限的普通开发环境操作。

## 开始前确认

- 确认目标环境、服务名称、版本号和变更单。
- 保存当前版本、配置版本和数据库迁移状态。
- 确认发布负责人、观察人和可用的回滚版本。
- 检查监控、日志、健康检查和告警渠道能够正常使用。

## 操作步骤

1. 在发布前记录请求量、错误率、P95 延迟、实例数和资源使用基线。
2. 先向最小灰度范围发布新版本，等待健康检查全部通过。
3. 对灰度实例执行核心接口探测，确认读写路径和依赖调用正常。
4. 对比灰度与旧版本指标；超过变更单规定的停止条件时，不再扩大范围。
5. 指标稳定后分批扩大范围，每批结束后重复健康检查和业务验证。
6. 出现异常时保存现场信息，然后回滚应用版本或恢复上一份配置。
7. 回滚后继续观察，直到指标恢复到发布前范围并补充故障记录。

## 检查方法

- 所有实例的就绪检查和存活检查均通过。
- 核心业务接口返回成功，且没有新增持续性错误日志。
- P95 延迟、错误率和资源使用未超过发布停止条件。
- 回滚演练能够在约定时间内恢复旧版本。

## 常见问题

- 一次替换全部实例：失去灰度观察和快速停止机会，应分批发布。
- 异常时先清理日志：会丢失排查依据，应先保存时间点、实例和请求信息。
- 配置变更没有版本：回滚时无法准确恢复，应在发布前保存配置版本。
- 应用已回滚但数据无法兼容：发布前必须检查数据库迁移是否支持旧版本。

## 完成标准

- 目标实例全部运行指定版本且健康检查正常。
- 核心业务指标在约定范围内保持稳定。
- 发布记录包含实际版本、时间、观察结果和必要的恢复信息。
