# 可供选择的工具

整理日期：2026-09-06。用于数据集编写和标签审核，不作为额外提示词注入，也不要复制到任务 Workspace 中。

本文先列出 Memory / Skill Proxy Tool，再列出数据集中的具体 Skill。两者不是同一层：`skill_view` 是工具，`postgres-safe-migration` 等是通过该工具读取的 Skill。

工具 description 来自当前 Native Registry；简介只帮助阅读，不替代原始描述或参数 Schema。不包含 Knowledge Tool、Claude Code 的 Bash/Read 等客户端工具，也不包含模板目录中的示例 Skill。

## 1. Memory Proxy Tool（6 个）

需要开启 Memory 能力并具备相应的会话权限。L0 是原始对话，L1 是提炼后的记忆，L2 是场景记忆，L3 是长期画像。L3 正文和 L2 索引可以自动注入；L0/L1 通常由模型主动调用工具查询。

| 名称 | 原始工具描述（description） | 简介（人话） |
|---|---|---|
| `tdai_memory_search` | 搜索 L1 原子记忆（双路 hybrid: dense vector + BM25），按相关度排序。默认跨当前 Agent 的 self + imported 记忆检索；返回项里的 source_agent_* 表示来源。适合回忆用户偏好、历史结论、规则等。 | 查以前提炼好的偏好、规则和项目结论，也可以查已授权借入的记忆。 |
| `tdai_atomic_query` | 按 type / 时间窗 / 分页拉取 L1 记忆（不做语义检索）。 | 按记忆类型、时间范围和分页条件列出记忆，不是按关键词搜索。 |
| `tdai_conversation_search` | 在 L0 原始对话中检索（比 tdai_memory_search 粒度更细，找具体消息原文 / 引用 / 时间线）。默认跨当前 Agent 的 self + imported 记忆检索；返回项里的 source_agent_* 表示来源。 | 到原始聊天里找具体说过的话、讨论过程或历史事件。 |
| `tdai_conversation_query` | 按 session 顺序取 L0 历史消息。 | 知道会话 ID 后，按顺序读取那次会话的原始消息。 |
| `tdai_scenario_ls` | 列出 L2 scene_blocks 路径索引（含 summary，不含正文）。一般 system 已注入索引，需刷新/按前缀过滤时才用。 | 查看场景记忆的目录和摘要，不读取正文；通常已有目录，不必重复列。 |
| `tdai_read_scene` | 按 path 读取 L2 场景文件全文。path 必须先从 `<l2_scene_index>` 或 tdai_scenario_ls 获取，不要凭空构造；读取 imported_from 分段的 path 时带上该分段 agent_id。 | 按照已知目录路径打开一份场景记忆，读取完整内容。 |

说明：description 中的 hybrid/dense/BM25 是工具能力描述，不能据此认定实验环境已启用向量检索。`tdai_conversation_query` 上表描述的是工具契约；指定历史会话的实际可用性还应核对导入后的会话 ID 和 Bridge 行为，不能只凭标签认定检索成功。

## 2. Skill Proxy Tool（通常开放的 4 个）

需要开启 Skill 能力并具备相应的会话权限。`skill_extract` 虽然与读取工具一起开放，但会触发归档和后台提取，不属于严格意义上的只读操作。

| 名称 | 原始工具描述（description） | 简介（人话） |
|---|---|---|
| `skill_search` | 在**你在团队中有权限访问**的 skill 中按关键词 + 语义检索匹配项（跨 agent，但**不含**其他人设置为私密的 skill —— 与前端「团队资产」tab 展示一致）。query 必须是非空字符串，建议写 2-5 个相关关键词。当你觉得自己自带的 skill 不够用时，用它发现团队里其他可用的 skill。返回条数由服务端固定，若结果不理想请换一组关键词重试，不要添加 top_k/mode 等 Schema 中未定义的参数（会被拒绝）。 | 当前自带 Skill 不够时，到有权限访问的团队 Skill 中找相关方法。 |
| `skill_view` | **打开一个 skill 的入口**：拿到 SKILL.md 全文 + 资源目录树（manifest）。想读某个资源文件的字节，必须先调这个工具从 manifest 里挑出 path，再用 skill_files_read。skill_name 用 `<available_skills>` 里 `- name: description` 那个 name，或 skill_search 结果里的 name 字段。 | 按 Skill 名称打开使用说明，并查看它附带的文件目录。 |
| `skill_files_read` | 读取单个资源文件内容。**必须先调 skill_view 拿 manifest**，从里面挑出 skill_id + path，本工具才能定位。返回文件内容及编码等信息。 | 读取 Skill 附带的参考文档、脚本或其他文件；先从 skill_view 取得文件位置。 |
| `skill_extract` | 立即归档当前对话触发一次 skill 抽取（异步任务，由后台 agent 分析对话内容生成 skill）。使用当前会话已累积的对话，你不用传 messages。适合在"用户已经跑通一段完整流程、值得复用"时主动触发。 | 把当前会话归档，交给后台尝试整理成可复用的 Skill；不是立即返回一份现成 Skill。 |

`skill_extract.reason` 是可选参数，用于说明为什么这段会话值得提取，不是必须满足的额外调用条件。

## 3. Skill 写工具（已实现，当前未开放的 6 个）

这六个工具受 `skillRuntime.allowLlmWrite` 控制。当前配置为 `false`，不要将它们标成当前评测任务必须选择的工具。下表收录它们是为了展示完整能力，不表示已经开放。

| 名称 | 原始工具描述（description） | 简介（人话） |
|---|---|---|
| `skill_create` | 新建 skill；owner 自动 = 当前 agent。 | 给当前 Agent 新建一个 Skill。 |
| `skill_update` | 替换 SKILL.md（version+1）。 | 整篇替换一个 Skill 的 SKILL.md，保存为新版本。 |
| `skill_patch` | SKILL.md 子串替换（避免大 diff）。 | 通过字符串替换修改 SKILL.md 中的一段内容。 |
| `skill_delete` | 永久删除当前 Agent 拥有的 Skill，包括所有版本和资源文件。 | 彻底删除一个属于当前 Agent 的 Skill，包括历史版本和附件。 |
| `skill_files_write` | 增/改资源文件（version+1）。 | 给 Skill 新增附件，或覆盖已有附件，保存为新版本。 |
| `skill_files_remove` | 删资源文件（实际删除文件时 version+1）。 | 删除 Skill 的指定附件；确实删到文件才生成新版本。 |

参数要求仍以 Schema 为准，例如 `skill_create` 的正文要包含 frontmatter，`skill_patch` 默认要求原文本唯一匹配。Baseline 旧提示词将 `skill_delete` 写成“软删”，本文采用与当前实际行为一致的永久删除说明。

## 5. 审核标签时注意

- 工具名和 Skill 名分开：`allowed_first_tools` 填 `skill_search` / `skill_view` 等工具名；`expected_skills` 填具体 Skill 名称。
- Skill 已在目录中且名称已知时，可以直接 `skill_view`，不必先 `skill_search`。读取附件一般先 `skill_view`，从返回目录取得 `skill_id` 和 `path`。
- Memory 查询和读取有不同用途：搜索事实、按条件列记忆、读取会话、查看场景目录、读取场景正文，不能只因为都属于 Memory 就视为可以任意互换。
- 是否应调用不能只看任务难度。需要同时检查任务缺少什么信息、现有上下文是否已给出答案，以及实际 System Prompt 的要求。
- 当前两组 Skill 引导要求加载相关或部分相关的 Skill。因此“简单任务能独立完成”并不能自动推出 `should_call=false`。这属于标签审核问题，本文不修改已有标签。
- 记录到了 `skill_view`，只说明选择了这个工具；不校验参数，就不能证明读取了正确的 Skill。
