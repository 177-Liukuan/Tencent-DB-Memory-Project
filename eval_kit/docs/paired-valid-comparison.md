# 同题有效观测对比

## 统计范围

主对比按同一实验内的 `suite + case_id + repeat` 配对，只纳入双方 `observation_valid=true` 且 Query、初始资产版本和有效评分规则一致的任务。任意一边无效或记录缺失，整对暂不纳入；标签或输入不一致也单独说明。重复记录报错，不以后写覆盖前写。

不依据实际调用、选对与否或最终回答是否完成筛选。正常完成但无调用是有效结果；已经记录调用、随后到达观测点停止或后续 Coding 未完成，也不抹去有效调用。初始化失败等无效观测不能冒充“未调用”。

指标公式、Bridge 接收顺序、事件去重和观测有效判断没有改变：

- 有效调用率：已调用正样本 / 同题正样本。
- 误调用率：发生调用的负样本 / 同题负样本。
- 工具选择正确率：首次选对的正样本 / 本组已调用正样本。两组调用情况不同，分母仍可不同；不要再筛成双方都调用的子集。
- Memory、Skill、Mixed、None 四组都从同一配对集合统计；Mixed 不进入纯 Memory 或 Skill 正样本组。
- 两类工具误调用率以配对集合中的全部 None 为分母。None 同时调用两类工具，两类各计一次，总误调用只计一次。
- 分母为零返回 `null`，页面显示“—”，不是 0%。

同题筛选不能消除所有偏差：异常若集中在难题，剩余任务仍可能更容易。因此结果只能称为“双方观测均有效任务上的对比”，必须同时报告全部运行的异常情况。

## 汇总和页面

`summarizeObservationRuns()` 同时供流水线、`score` 命令和 Viewer 使用：

- `primary_scope: "paired_valid"` 明确默认范围。
- `paired_comparison.baseline/native`：主指标，包含计数和分组结果。
- `paired_comparison.total_pairs/included_pairs/excluded_pairs/items`：已经有记录、可确定 suite 的配对数量和逐题纳入状态、排除原因。
- 顶层 `baseline/native`：原来的各组全部记录统计，供观测完整性和参考区使用。
- `by_suite`：各评测分组同时提供以上两种范围。
- `paired_latency`：另外要求配对双方有完整回答与有效耗时；`tool_calls` 模式不测完整任务延迟。

Viewer 顶部的“计划对数”和“运行记录进度”来自 manifest，覆盖全实验；主指标和观测完整性限定在当前选择的 suite。两边结果都缺失或损坏时，尚不知道该题属于哪个 suite，单独显示“分组待定”，不能混进已知分组的分母。完整实验中这些数量应对得上。

页面默认显示同题主指标及每项分子/分母。观测完整性保留每组全部记录，不做配对剔除；参考统计折叠展示，不标注两组提升。任务列表保留全部记录，可筛选“纳入/未纳入主对比”，筛选不改变上方指标。未纳入任务的详情仍显示两组真实调用，不把有效一侧说成失败。

## 更新已有实验

备份原 `summary.json` 后，在 `eval_kit` 执行：

```bash
npm run score -- --experiment results/<experiment_id>
```

只读取原运行记录并更新汇总，不读取当前任务标签，不修改 Query、调用、顺序、时间或完成状态，不运行 Claude Code。Viewer 按运行记录实时计算，无须依赖预先生成的 summary。

本次核对实验 `pilot-2026-09-07T10-07-49-526Z`：285对、570条记录，259对纳入、26对未纳入；配对正样本199、负样本60。Baseline全部记录264有效/21无效，Native277有效/8无效。

| 主指标 | Baseline | Native |
|---|---:|---:|
| 有效调用率 | 194/199（97.49%） | 193/199（96.98%） |
| 误调用率 | 25/60（41.67%） | 25/60（41.67%） |
| 工具选择正确率 | 138/194（71.13%） | 129/193（66.84%） |

验证包含配对统计、Viewer API、流水线重新汇总、完整 Vitest 和类型检查，以及 `tests/viewer-paired.browser.js` 的只读浏览器检查。
