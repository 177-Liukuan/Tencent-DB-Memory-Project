# 9 Task Pipeline 验证计划

> 此文件保留早期执行计划。用户后来明确要求工具指标与完整 Coding 分开，最终入口默认 `tool_calls`，到指定事件即停止；准备改为独立 Core 顺序执行，不改在线调度。当前运行办法以 `pilot-pipeline.md` 为准，实际完成范围与失败证据以 `pilot-9-task-report.md` 为准。不得把下述旧的“完整运行到底”要求当作当前目标。

本次只验证流程，使用现有 Query 和标签，不据此下实验结论。Memory、Skill、None 各取三个不同场景、有项目素材的 main 案例，按 case_id 排序选择，保存选中数据。

1. 检查项目版本、服务、鉴权、观测目录及数据引用。整个过程只修改 eval_kit，不修改两组工具实现。
2. 每个 Task、每个版本新建独立普通用户 / Team / Agent / Task，使用同样的中性描述。CLI 再生成独立 Session，放入只挂载本 Task 素材的临时容器。
3. 导入该 Task 引用的历史对话和候选 Skill。Memory 先在 Baseline 的新 Agent 中完成真实提炼，等待 L1/L2/L3 完成；只复制该 Agent 的记录、检索索引和场景/画像文件到配对的新 Native Agent，不覆盖整个 Core。两组核对内容后才开始运行。
4. 当前第一版复制器只支持本机 SQLite + 本地文件存储，目标必须为空。不存在的表、模式不一致、提炼失败均明确停止，不自动降级。数据准备时间不计入端到端延迟。
5. 使用同样的模型、工具权限、超时和资产，交替两组先后顺序。真实执行工具、不 Mock、不提前在首次工具调用时结束。保留原始 CLI 输出、Bridge 事件及最终回答。
6. 汇总 18 次结果和配对延迟，检查独立身份、导入数量、资源正文、事件归属、完成状态和异常。生成报告，一键入口串起以上步骤。

已发现待修复：旧准备入口整体替换 Core、身份共用，不符合此次隔离需求；CLI 默认只允许 curl，不能执行正常 Coding 命令；Skill 导入器只读 files/，会漏掉当前数据集的 references/ 和 scripts/。

边界：首次需已有可用部署和凭据；不自动安装整套业务服务。新实验不复用已有 Agent，失败数据保留以供排错。不自动清理或覆盖人工会话。
# 本次追加确认

- 保留“同一 Core 提炼一次、两组共享同一初始内容”的公平性原则；只复制新建 Agent 范围，不替换完整 Core。
- 独立准备进程复用原 Core 的提炼函数，等待全部 L1 → L2 → L3，不改生产调度规则。
- 在线 Core 保留 4096 默认预算。仅准备进程在实际截断时明确配置为 8192，不使用 16384。
- 原 Standalone 默认关闭 embedding；本轮固定相同 BM25 并核对真实查询，不声称已测向量语义检索。
- Agent 使用通用名称和描述；Task、版本、重复实验分别使用独立项目副本。
