# 分段数组的限时填充与缺项还原

一道数据结构设计题，考察乱序填充、重复写入判定、过期淘汰，以及按原始位置还原缺失元素。本目录是独立算法示例，不依赖数据库、网络或其他项目模块。

## 题目

有一个包含 `m` 行的二维数组，每行由若干片段按创建顺序拼接而成。行号从 `0` 开始。

创建片段时，元素编号及顺序已经确定，数值尚未填写。数值逐个到达，可能乱序或重复。所有位置在有效期内填写完成后，片段才能用于长期恢复。

每个位置有一个标记：

- `keep[i] = 1`：元素会保留在后续提供的残缺数组中。
- `keep[i] = 0`：元素会被删除，需要保存必要信息来还原。

请实现 `SequenceRestorer(m, ttl)`，既能查询尚未填写的位置，也能在填写状态过期后还原所有已完成片段。

编号只标识身份，不表示排列顺序。数值相同的元素也不能合并。

### 接口

#### `append(row, ids, keep, now) → segmentId`

在指定行末尾创建片段。`ids` 是原始排列顺序，`ids` 与 `keep` 长度相同且非空；元素编号全局唯一。片段编号从 `1` 开始递增。

片段在 `now + ttl` 时到期，任何写入都不会延长有效期。输入保证上一片段已经完成或过期，且传入的 `row` 非递减。

#### `write(segmentId, id, value, now) → status`

- `WAITING`：首次写入，但尚未填满。
- `COMPLETE`：首次写入且刚好填满，立即保存恢复信息。
- `DUPLICATE`：该位置已填写，数值相同。
- `CONFLICT`：该位置已填写，数值不同；保留原值。
- `EXPIRED`：填写状态已到期，不再接受写入。

过期判断先于重复判断；输入保证片段和其中的元素编号曾被创建。

#### `missing(segmentId, now) → ids | null`

返回尚未填写的编号，保持原始顺序。填满但未到期时返回 `[]`；已到期返回 `null`。

#### `restore(visible, now) → restored`

`visible` 包含 `m` 行，每个元素为 `[id, value]`。输入保证其中恰好包含所有已完成片段的 `keep = 1` 元素，完整、无重复、数值正确且顺序不变；不包含未完成片段的元素。

返回补全的二维数组：

- 保留全部行，包括空行。
- 行内按片段创建顺序拼接，片段内按原始 `ids` 顺序排列。
- 已完成片段不受填写状态到期影响。
- 未完成片段不参与恢复，未完成就到期的片段整体丢弃。
- 不修改输入；相同状态、相同输入下，多次恢复结果一致。

### 存储限制与约束

长期记录可以保存编号、位置及 `keep = 0` 的数值，不能永久保存 `keep = 1` 的数值；恢复时必须从 `visible` 读取这些数值。有效期内的填写状态不受此限制。

- `1 ≤ m, ttl ≤ 100000`。
- 操作次数和创建元素总数各不超过 `100000`。
- 所有 `now` 单调不减；恰好到期即失效。
- 时间、编号和数值均为整数；本 TypeScript 实现使用 JavaScript 可精确表示的安全整数，`now + ttl` 也应在该范围内。
- 不使用真实计时器或磁盘存储。“长期”仅表示不随填写状态一起到期。
- 实现依照题目的合法输入保证，不额外定义非法行号、重复编号等输入的行为。

## 示例

```text
SequenceRestorer(2, 10)

append(0, [7, 3], [0, 1], 0) → 1
write(1, 3, 20, 1) → WAITING
missing(1, 1) → [7]
write(1, 3, 20, 2) → DUPLICATE
write(1, 3, 99, 2) → CONFLICT
write(1, 7, 10, 3) → COMPLETE

append(0, [9], [0], 4) → 2
write(2, 9, 30, 5) → COMPLETE

append(1, [2], [1], 6) → 3
write(3, 2, 40, 7) → COMPLETE
missing(1, 10) → null
```

时间 `20` 时，所有填写状态都已到期：

```text
visible = [
  [[3, 20]],
  [[2, 40]]
]

restore(visible, 20) = [
  [[7, 10], [3, 20], [9, 30]],
  [[2, 40]]
]
```

`7`、`9` 的值来自恢复记录，`3`、`2` 的值来自 `visible`。`9` 属于后来追加的片段，必须在 `3` 后面，不能因为它被删除就统一放到行首。

## 解题思路

### 1. 用哈希表维护填写状态

以片段编号索引尚未过期的状态。每个片段保存原始 `ids`、`keep`、到期时间，以及 `id → value` 的哈希表。

写入时先清理到期状态，再判断重复或冲突。首次写入后，哈希表大小等于片段长度就说明刚好完成。`missing` 遍历原始 `ids`，筛出尚未填写的编号，所以不受实际到达顺序影响。

完成后仍保留填写状态直到到期，用来判定后续的重复和冲突；重复写入不会再次归档。

### 2. 只归档恢复必需的信息

完整片段按原始顺序追加到对应行的恢复记录中：

```text
保留位置：{ id, keep: 1 }
删除位置：{ id, keep: 0, value }
```

由于前一片段必须完成或过期后才允许追加，完成片段的归档顺序就是所需的创建顺序。数组位置已经表达顺序，不需要另存排序键，也不需要保留片段边界。

到期清理只删除填写状态，不触碰恢复记录。保留位置的值未写入恢复记录，因而不会被长期保留。

### 3. 按序合并，不按编号排序

恢复时逐行扫描恢复记录，并为该行的 `visible` 设置一个游标：

- 遇到删除位置，使用记录中的值。
- 遇到保留位置，读取游标指向的可见值，再前进一步。

输入已保证可见元素完整且有序，所以不需要为 `visible` 另建哈希表。输出中的每个 `[id, value]` 都新建，避免调用方修改输出时影响输入或后续恢复。

### 4. 利用到期时间有序这一条件

TTL 固定、创建时间单调，到期时间自然有序。JavaScript 的 `Map` 按插入顺序迭代，足以兼任有序清理队列：从头删除到期片段，遇到第一个未到期片段就停止。

每次接口调用都执行清理；没有操作时不启动后台计时器。过期状态在下一次操作进入时解除引用，不会仅返回 `EXPIRED` 却永久保留其数值。

## 复杂度

设当前片段长度为 `k`，已完成元素总数为 `n`，未过期状态中的元素总数为 `a`。

- `append`：`O(k)`，用于复制输入。
- `write`：普通写入、重复或冲突平均 `O(1)`；完成片段的那次写入为 `O(k)`。每个元素只归档一次。
- `missing`：未过期时 `O(k)`；过期后查找平均 `O(1)`。
- `restore`：`O(m + n)`，与输出规模相同。
- 空间：`O(m + n + a)`，不计返回数组。长期记录只保留被删除位置的值。

上述单次复杂度不含本次到期清理：若清理 `e` 个片段，额外需要 `O(e)`；但每个片段只删除一次，全部操作的清理总次数不超过片段数。哈希表操作按通常的平均复杂度计算。


测试包含题目示例、边界用例、固定种子的随机数组模型对照，以及十万次操作规模检查。对照模型为方便验证而保留全部数组，属于测试代码，不是满足长期存储限制的参考解法。

核心区别：填写状态记录“还有什么没完成”；恢复记录描述“完成后的数组原本是什么顺序”。前者可以过期，后者不能随之丢失。
